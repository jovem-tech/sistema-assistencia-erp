# 2026-05-03 - Release v2.16.39 - Evolution API + Central Omnichannel

## Objetivo da entrega

Adicionar suporte nativo a `Evolution API` como provider direto do WhatsApp, preservando o ERP como fonte de verdade da Central de Mensagens e permitindo o mesmo historico para:

- mensagens recebidas do cliente;
- respostas humanas feitas no ERP;
- respostas humanas feitas no app oficial do WhatsApp;
- respostas automatizadas por bot/IA.

## Entregas realizadas

Capacidades adicionadas:
- envio de texto via Evolution;
- envio de midia/documento via Evolution;

Arquivos impactados:

Evolucoes aplicadas:
- parser inbound passou a entender melhor payloads da Evolution;
- leitura de `remoteJid`, `participant`, `pushName` e midias estruturadas;
- deduplicacao mantida por `provider_message_id`;
- sincronizacao opcional de avatar do contato;
- lista de conversas e cabecalho da thread podem renderizar foto real do contato;
- mensagens outbound detectadas como externas (`fromMe=true`) passam a pausar a automacao da conversa;
- envio humano pelo ERP tambem pausa o bot automaticamente quando for bem-sucedido.

### Inbox dinamica com stream proprio da fila

Complemento aplicado na central para aproximar a experiencia de inbox do modelo usado por ferramentas como Chatwoot:

- rota nova `GET /atendimento-whatsapp/conversas/stream` para atualizar a fila lateral por SSE;
- reinicializacao do stream da fila sempre que os filtros mudarem;
- fechamento defensivo dos streams ao ocultar a aba e reabertura ao voltar;
- fallback automatico para polling da lista quando o SSE da fila nao estiver disponivel;
- protecao para bancos locais ainda sem `contatos.whatsapp_avatar_url`, evitando erro `500` durante a listagem.

### Favicon consistente em ambientes locais

Correcao complementar para remover `404` recorrente em `GET /favicon.ico` no ambiente local com `baseURL` em subpasta:

- telas auxiliares de autenticacao passaram a declarar favicon via `base_url('favicon.ico')`;
- paginas de erro HTML tambem passaram a apontar para o favicon correto do sistema;
- `welcome_message` deixou de usar `/favicon.ico` hardcoded, respeitando a URL base da instalacao.

## Arquitetura operacional consolidada

Fluxo recomendado:

`Cliente -> WhatsApp -> Evolution API -> ERP Central`

Fluxos paralelos suportados:
- `ERP -> Evolution API -> Cliente`
- `App oficial WhatsApp -> Evolution API -> ERP Central`
- `n8n -> ERP Central / Evolution API`

Resultado:
- uma unica thread operacional no ERP;
- sem perda de historico quando o atendente alternar entre ERP e app oficial;
- com contexto de cliente/OS preservado para operacao humana ou automacao.

## Complemento operacional n8n + Evolution + IA

Foi adicionada uma referencia oficial de workflow n8n para o desenho recomendado com Evolution como camada de transporte, n8n como orquestrador e ERP como historico oficial:

- workflow JSON:
  - `documentacao/10-deploy/n8n/evolution-whatsapp-atendimento-ia-erp.json`
- nota de implementacao:
  - `documentacao/07-novas-implementacoes/2026-05-03-workflow-n8n-evolution-atendimento-ia-erp.md`

Fluxo registrado:

`Cliente -> WhatsApp -> Evolution API -> n8n -> ERP/banco -> resposta ao cliente via Evolution`

Esse workflow:

- aceita `MESSAGES_UPSERT` da Evolution;
- ignora grupos e `fromMe=true`;
- espelha o inbound para `POST /webhooks/whatsapp`;
- consulta a tabela `clientes` do ERP;
- monta contexto de IA;
- responde pelo endpoint `POST /message/sendText/{instance}` da Evolution.
